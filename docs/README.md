# Portfolio Documentation

This folder contains all documentation for the portfolio project, organized by category.

## Folder Structure

```
docs/
├── animations/          # Animation system documentation
├── architecture/        # Project structure and architecture
├── components/          # Component-specific documentation
└── archive/            # Outdated analysis and debugging files
```

## Contents

### `/animations` - Animation System

Current, up-to-date animation documentation:

- **ANIMATION_SYSTEM_DOCUMENTATION.md** - Overview of animation technologies and patterns
- **CURRENT_ANIMATIONS_INVENTORY.md** - Visual inventory of all animations with ASCII diagrams
- **CONTENT_SWITCH_ANIMATION_MAP.md** - Detailed breakdown of content switching animation
- **ANIMATION_SEQUENCE_DEBUG.md** - Final solution for animation issues

### `/architecture` - Project Architecture

High-level project structure documentation:

- **CONTENT_NAVIGATOR_ARCHITECTURE.md** - ContentNavigator component architecture
- **PROJECT_STRUCTURE.md** - Overall project structure and organization

### `/components` - Component Documentation

Component-specific implementation details:

- **CardCarousel-Documentation.md** - Card carousel component documentation
- **head-refactor-spec.md** - Head component refactor specification
- **annotations-behavior-doc.md** - Annotations behavior documentation

### `/archive` - Archived Files

Outdated analysis files kept for historical reference:

- **CONTENT_SWITCH_ISSUES_ANALYSIS.md** - Original issue analysis (outdated)
- **HEIGHT_CONTROL_ANALYSIS.md** - Height control debugging (outdated)
- **ANIMATION_TARGET_FIX.md** - Animation target analysis (outdated)

## Documentation Standards

### When to Create Documentation

- New major features or systems
- Complex animations or interactions
- Architecture decisions
- Component refactors

### Documentation Format

- Use Markdown (.md)
- Include code examples
- Add ASCII diagrams for visual concepts
- Keep descriptions clear and concise
- Update documentation when implementation changes

### When to Archive

Move documentation to `/archive` when:
- Implementation has changed significantly
- Analysis was for debugging (problem now solved)
- File is superseded by newer documentation
- Still useful for historical reference
